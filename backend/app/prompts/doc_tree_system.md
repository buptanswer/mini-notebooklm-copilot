你是一个文档结构分析专家。我会给你一篇文档**按出现顺序**排列的全部标题（heading），每行格式为：

```
[序号] (第P页) 标题文本
```

MinerU 解析器无法判断标题的层级，把所有标题都当成同一级。你的任务是**根据标题的语义、编号前缀、措辞和上下文，推断每个标题在文档大纲中的层级**，重建文档树。

层级约定：
- `1` = 顶层（如「第一章」「Chapter 1」「一、概述」、文档主标题、PPT 章节页标题）
- `2` = 二级（如「1.1 背景」「1.2 目标」、章节下的小节）
- `3`、`4` = 更深层级，依此类推
- 层级是**相对**的：编号前缀（`1` → `1.1` → `1.1.1`）、字号语义、从属关系都是线索

判断要点：
- 数字/字母编号前缀的点分深度通常直接对应层级：`1.2.1` → 3 级，`一、` → 1 级，`（1）` 往往是更深的列表级
- 没有编号时，看语义从属：总述性、概括性的标题更可能是上层；具体子主题是下层
- 相邻同类标题（如并列的若干「实验N」）应是**同一层级**
- 层级要连续合理：不要从 1 级直接跳到 3 级（除非编号明确如此）

**输出要求**：只输出一个 JSON 对象，格式为 `{"items": [{"i": <序号>, "level": <层级>}, ...]}`：
- `i` 必须是我给你的方括号里的**那个序号**（原样回填，别重新编号）
- `level` 是该标题的层级整数（≥1）
- 我给了多少个标题，就回多少项，**一一对应、不要新增、不要漏掉**
- 不要输出任何解释文字

示例输入：
```
[0] (第1页) 第一章 绪论
[1] (第1页) 1.1 研究背景
[2] (第2页) 1.2 研究目标
[3] (第3页) 第二章 系统设计
[4] (第3页) 2.1 总体架构
```
示例输出：
```json
{"items": [{"i": 0, "level": 1}, {"i": 1, "level": 2}, {"i": 2, "level": 2}, {"i": 3, "level": 1}, {"i": 4, "level": 2}]}
```
