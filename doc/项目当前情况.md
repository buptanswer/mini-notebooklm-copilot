## 1、项目概述

本项目是一款面向大学生课程学习场景的**本地化多模态个人知识库与 AI 辅导系统**（Mini-NotebookLM）。它由两部分组成：

1. **通用多模态 AI 知识库底座**（模块一~六）：PDF/PPT/Word/图片的高保真解析、结构化切片、向量 + 关键词混合检索、重排序、多模态问答与高亮溯源；v1.2.0 起原生支持 `.txt`（课堂录音转写）/`.md`（讲义、笔记）两种纯文本类型，并新增「本地文件夹绑定」模式。
2. **场景 AI Agent 模块**：在底座之上针对大学生痛点提供垂直辅学功能——**模块七 AI 伴学·课后复盘**（已实现）、**模块九 AI 管家·课程信息卡片**（已实现）；**模块八 AI 考官·出卷判分**与音视频转写作为提升项，本期未实现。

系统采用前后端分离架构，在本地 Windows 环境运行，核心解析、向量化、重排序、问答能力依托云端 API。

**技术路线**：MinerU 高保真解析 → 自研 IR 标准化中间层（重建文档树、注入标题路径、坐标锚点）→ Parent/Child 结构感知切片 → 向量 + BM25 双路混合召回 → qwen3-rerank 重排 → 多模态旗舰模型问答。

**约束**：单人 + AI 编程助手开发；坚持 KISS，不引入 LangChain 等重封装框架，优先原生 SDK 与透明数据流。

## 2、已实现的功能模块

系统划分为九大模块。模块一~六为基础 RAG 链路，模块七 / 九为场景模块（v1.2.0 已实现），模块八为提升项（仅建表，未实现）。

### 模块一：多格式资料接入与异步解析 ✅

**支持文件类型**：
- 文档/图片：`pdf`、`ppt/pptx`、`doc/docx`、`png/jpg/jpeg`、`xlsx/xls` —— 统一走 MinerU 在线 API（`/api/v4` 批量精准解析，`model_version=vlm`）。
- **纯文本（v1.2.0 新增）**：`txt`（课堂录音转写）、`md`（AI 讲义 / 用户笔记）—— **跳过 MinerU**，直接 UTF-8 读取，status 直接置 `text_only`。

**两种资料接入模式**：
- **上传模式**：浏览器逐个/批量上传文件至 KB（保留 `relative_path` 逻辑路径）。
- **文件夹绑定模式（v1.2.0 新增，课程 KB 必用）**：创建 KB 时填本地目录绝对路径（`knowledge_bases.bound_folder_path`），点「同步」按钮（`POST /api/kb/{kb_id}/sync-folder`，`folder_sync_service.py`）扫描目录登记文件；**不自动调用 MinerU**（省配额），由用户在文件页按需点「解析」；目录约定结构见模块七。消失的文件标 `missing` 不立即删库。

**解析流水线**（`pipeline_service.py`，16 步异步编排）：
1. `[A]` 申请 MinerU 批量预签名上传 URL → `[B]` PUT 上传 OSS → `[C]` 轮询任务取 `full_zip_url` → `[D]` 下载 ZIP
2. `[E]` 解压 + bundle 文件角色识别（`bundle_parser.py`）
3. `[E+]` **MinerU 格式严格审计**（`format_checker.py` → `data/format_probe_log.jsonl`）
4. `[F]` 归一化 `content_list_v2.json` → `IRBlock[]`（`normalizer.py`）
5. `[G]` DOM 重建 + `header_path` 注入（`dom_builder.py`）→ `[H]` 脚注关联 → `[I]` 读 `layout.json`
6. `[J]` 写 `document_ir.json` → `[IR-V]` IR 校验（`ir_validator.py`）
7. `[K-vlm]` 多模态富化：图片描述 / 表格摘要（`enricher.py`，VLM 模型可配）
8. `[L]` Parent Chunk → `[M]` Child Chunk → `[Chunk-V]` 校验 → `[N]` 向量化 → `[O]` Qdrant+SQLite 入库 → `[P]` JSONL 落盘 → 更新文档状态

**未实现**：音视频转写（飞书妙记 / 通义听悟）—— 提升项。

### 模块二：MinerU 数据解析与标准化 IR ✅

双层「宽进严出」架构：
- **Raw 层**（`models_raw_mineru.py`，`extra="allow"`）接收所有字段，未知字段触发 WARNING。
- **IR 层**（`models_ir.py`）严格 Pydantic 校验、枚举类型、坐标范围校验。

Normalizer 块类型映射：`title→title`、`paragraph→paragraph`、`list/index→list`、`image→image`、`chart→image`(chart_image)、`table→table`、`equation_interline→equation`、`code→code`、页眉/页脚/页码/脚注→同名辅助块。

Office 原生解析（DOCX/PPTX）特殊处理：所有块 `bbox` 键缺失，用 `[0,0,0,0]` 静默占位，校验器跳过 sentinel bbox；无 `origin.pdf`，前端隐藏「查看原文」。

落盘：`data/rag_output/{doc_id}/` 下 `document_ir.json` / `document_ir_enriched.json` / `parent_chunks.jsonl` / `child_chunks.jsonl`。

### 模块三：结构感知切片与多模态富化 ✅

- **Parent Chunk**（`parent_chunker.py`）：每个**有正文/叶子**的 `IRSection` 一个 ParentChunk；跳过 synthetic root，**v1.4.0 起纯标题容器 section（有子节、自身只有 title 无正文块）不单独出 ParentChunk**（消除"扁平→层级"后的退化父块）；图片/表格输出 `"[图片: caption]"` / `"[表格: caption]"` 占位。v1.4.0 加 `text_full` 落库供 Small-to-Big 用 parent 全文。
- **Child Chunk**（`child_chunker.py`）：原子块（list/code/image/table/equation）整体不拆；paragraph 滑动窗口切分（`max_tokens=250`/`min_tokens=150`/`overlap=0.15`）；`embedding_text = "{header_path}\n{text}"`；**v1.4.0 起 `title` 块不单列 child**（已在 header_path 前缀里）。
- **富化**（`enricher.py`，并发 3）：图片 base64 → VLM 中文**描述 + 转写图中文字**；表格 HTML → VLM 中文摘要；结果回流 `embedding_text` 增强检索。**v1.4.0：图片可检索文本基底改为 caption + 我们的 VLM 描述（弃用 MinerU 图片 OCR），命中图片时原图 base64 进多模态问答。**

### 模块四：索引、入库与混合检索 ✅

- **向量**（`embedding_service.py`）：`text-embedding-v4`（百炼，1024 维），Child Chunk 存 Qdrant（payload 含完整元数据）。
- **关键词**（`database.py`）：SQLite FTS5 虚拟表 `child_chunks_fts`（`unicode61`），触发器自动同步。
- **查询规划（v1.4.0）**（`query_planner.py` + `prompts/query_plan_system.md`）：检索前先由 LLM 把用户问题析出**关键词（给 BM25）** + **HyDE 式陈述句语义查询（给向量）**；失败回退朴素分词、不阻断。已接进真实问答 `conversation_service`。
- **混合检索**（`retrieval_service.py`）：关键词路用规划关键词（OR）、向量路用语义查询，双路并行召回，RRF 融合（`k=60`），融合后 top_k=15。
- **重排序**（`rerank_service.py`）：`qwen3-rerank`（DashScope 专有端点，不可换 Provider），top_k=15 → top_n=5。
- **检索 trace（v1.4.0）**（`retrieval_trace.py`）：把"规划→双路→RRF→重排"全链路产出结构化 trace，端点 `POST /api/chat/{kb}/retrieve-trace` 驱动「检索透视」页（纯检索、不生成答案）。

### 模块五：多模态问答与提示词编排 ✅

- **QA Service**（`qa_service.py`）：**v1.4.0 Small-to-Big——命中 child 后用其 parent 全文（`text_full`）作上下文**（多 child 命中同 parent 去重），而非只用 child retrieval_text。
- **多模态最终问答（v1.4.0）**：`QA_ENABLE_MULTIMODAL` / `QA_MULTIMODAL_MODEL`(默认 `qwen-vl-max`)；命中图片切片时把原图 base64 作为 image part 拼进 QA 消息（限张数），纯文本路保留为回退。
- **多 Provider**：`QA_BASE_URL`/`QA_API_KEY`/`QA_MODEL` 切换任意 OpenAI 兼容 Provider（默认百炼 `qwen-plus`，可切 DeepSeek/OpenAI/Moonshot）。
- **SSE 流式**：v1.3.0 起所有对话端点统一为一套词汇 `conversation / message_start{role,message_id,metadata} / citations / thinking / delta / message_end / done / error`（由 `conversation_service.stream_turn` 产出，详见模块六/RELEASE_NOTES）。
- **提示词目录**（`backend/app/prompts/`，v1.2.0 外置）：5 个模板 + 加载器，`GET /api/settings/prompts` 只读展示、`POST /api/settings/prompts/reload` 热重载。

### 模块七：AI 伴学·课后复盘 ✅（v1.2.0 实现）

**定位**：基于课堂录音转写自动生成「老师口吻」的逐节讲义，并在同一对话上下文内多轮答疑、对话分叉。

**目录约定**（课程 KB 绑定的本地文件夹）：
```
<课程名称>/
  课堂录音/<YYMMDD>/
      <课程>YYMMDD第NN节.txt          ← 录音转写（每小节一份）
      <课程>YYMMDD第NN节课堂要点.md   ← AI 生成的讲义（保存后出现）
  课件/  作业/  通知/                  ← 模块九检索用
```

**实现**：
- 服务：`lecture_review_service.py` + `conversation_service.py`（多轮对话基座）。
- API：`api/review.py`（`dates` / `sections` / `generate` / `save-notes` / `notes` / `conversations` / `followup`）+ `api/conversations.py`（CRUD / `send` / `fork`）。
- 前端：`ReviewPage.tsx`，复用统一 `ChatThread`——讲义各节（`metadata.kind==="section"` 的 assistant 消息，按阅读卡片特化渲染）与追问（普通轮）同处一条线程。
- 提示词：`lecture_review_section_first.md`、`lecture_review_section_subsequent.md`、`lecture_review_followup_system.md`。
- 流程：选日期 → 读该日期目录全部 `*.txt` 按「第 N 节」排序 → 同一 conversation 内逐节调用 `stream_turn`（录音作 `hidden_user`，section 元数据打到 assistant；首节/后续节模板）生成讲义 → 「保存到本地」写 `.md` 并**自动切片入库**（`text_index_service`）→ 同会话追问 → 对任意 assistant 消息 **fork**（子会话不污染主线）→ **思维链开关**（思考与回答均流式；可「展开/收起思维链」）。

### 模块八：AI 考官·出卷判分 ⏳（提升项，未实现）

仅数据库就绪（`exam_questions` / `exam_papers` / `exam_submissions`），无后端服务、无前端页面。未来方向：Markdown 题库 → AI 组卷（含数值变形）→ 答卷拍照 **MinerU 解析 + LLM 逐题对照判分**。

### 模块九：AI 管家·课程信息卡片 ✅（v1.2.0 实现）

**定位**：从课程 KB 已绑定资料中自动抽取关键信息生成结构化卡片，并对临近截止日防遗漏提醒。

**实现**：
- 服务：`course_info_service.py`。
- API：`api/course_info.py`（`generate` / `get` / `upcoming-deadlines` / `delete` / `chat`）。
- 前端：`CourseInfoPage.tsx`（卡片网格 + 重新生成 + 追问聊天面板）。
- 提示词：`course_info_extract_system.md`、`course_info_chat_system.md`。
- 流程：5 个固定查询（考核方式 / 作业 DL / 考试时间 / 老师联系方式 / 重要通知）触发混合检索 → LLM **一次结构化 JSON 抽取** → 写 `course_info_cards`（含 `deadlines_normalized` JSON）→ 卡片展示 → 基于卡片在多轮对话基座上追问。
- **截止日 banner**：进入课程 KB 任何页面，若未来 7 天内有 deadline → 顶部黄色提醒。
- **`days_left` 实时重算**：卡片读取时（`get_card`）按当天从权威的 ISO `date` 字段重算 `days_left`，避免生成时算好的值随时间过期（v1.2.0 回归修复，`test_v120.py` 有对应回归用例）。

### 4.5 MinerU 格式漂移监控

`format_checker.check_bundle` 在流水线 [E+] 对每次解析做字段/文件层面的严格审计；有偏差才追加 `data/format_probe_log.jsonl`（无偏差不写）。独立探针 `tools/mineru_format_probe.py`（`--online` 消耗配额；退出码 0/1/2/3 = clean/error/warning/info）。**盯住该 jsonl 文件增长**；出现新格式时同步更新 normalizer/format_checker 已知字段集合与两份 MinerU 文档（见 §7）。

### 4.6 前端关键技术点

- SSE：`fetch + ReadableStream`（非 EventSource），支持 `AbortController`；v1.3.0 收敛为单一 `runSSE` 解析器，按统一词汇 `conversation/message_start/citations/thinking/delta/message_end/done/error` 驱动 `useConversation`。
- 统一会话基建：`useConversation` hook 管理一条会话的 messages 线程（流式 / 思维链函数式更新 / 历史线程化重载）；`<ChatThread>` 统一渲染（含任意消息 fork、citations、Markdown），`<Composer>` 统一输入。三个对话页全部复用。
- 设计系统：Tailwind v4 `@theme inline` token；`data-theme` 三主题（浅/暗/sepia，`ThemeSwitch`+`useTheme`，localStorage 持久化）；Fraunces×Hanken 字体；`motion` 动效（流式光标 / 思维链 shimmer / 入场，尊重 reduced-motion）。
- PDF bbox 高亮：`react-pdf` 渲染 + 绝对定位 `<div>` 高亮框，`bbox_norm1000`（0–1000）换算页面百分比。
- Markdown：自定义 `.md-prose`（不依赖 `@tailwindcss/typography`，规避 Tailwind v4 preflight 列表重置）。
