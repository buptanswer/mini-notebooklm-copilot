# 文档导览

接手开发时的阅读顺序：先看根目录 `progress.md`（进行中任务的实时状态），再看 `doc/项目当前情况.md`（已实现的稳定快照），即可建立全局认知并接着干。

## 核心文档

| 文档 | 位置 | 作用 |
|------|------|------|
| `progress.md` | **项目根目录** | **进行中任务的实时状态**：在做什么、计划/阶段、自上版以来改了哪些文件怎么改、下一步、如何验证。长任务每完成一小步即更新；任务验收后精简。接手第一篇读它。 |
| [项目当前情况.md](./项目当前情况.md) | `doc/` | 项目此刻**已实现到什么程度**的稳定交接文档，**必须与代码一致**；每次发版更新。 |

> 历史上的「下一步开发目标 / 开发实施手册」两篇规划文档已并入 `progress.md`（其角色就是"实时计划 + 进度"）。完整产品需求/愿景如需查阅，可从 v1.2.0 的 git 历史找回。

## 维护约定

- **进行中的长任务**：随时更新根目录 `progress.md`（见全局 CLAUDE.md「长任务：维护 progress.md」约定）。
- **每轮开发完成后**：更新 `doc/项目当前情况.md` + 根目录 `README.md` + `RELEASE_NOTES.md`。
- **MinerU API 出现未知 / 错误字段**：更新《在线API输出文件格式（SaaS推断版）》，并同步 `backend/app/adapters/normalizer.py` + `format_checker.py` 的已知字段集合（漂移信号来自 `data/format_probe_log.jsonl` 增长）。
- **解析 / 入库工作流变化**：更新《MinerU to RAG Pipeline 架构设计与数据流方案》。
