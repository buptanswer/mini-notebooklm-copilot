## 1、任务概述

### 1.1、目标

本项目旨在开发一款适合大学课程学习场景的"本地化多模态个人知识库与 AI 辅导系统"。它可以理解为一个 Mini-NotebookLM：保留知识库问答系统最核心的工程主线，控制范围和复杂度，使其适合作为程序设计实训课程中的课程设计项目。

系统采用现代前后端分离架构，在本地 Windows 环境中运行，但核心解析、向量化、重排序和问答能力依托云端 API。

**当前完成状态（2026-05-21）**：基础版本 v1.0.0 已完成并发布。核心 RAG 链路全部跑通，后端 API 测试 49/49 通过，TypeScript 0 错误，前端生产构建通过。三个场景扩展模块（AI 课后复盘、AI 出卷、AI 日程防呆）的数据库基础已就绪，前端页面待实现。

本项目的核心工程目标：

1. 用专业解析服务把复杂资料尽可能高保真地结构化
2. 通过自研 IR 标准化层重建文档结构、注入标题路径、建立坐标锚点
3. 使用效果更稳定的纯文本向量模型做召回
4. 增加重排序环节提升相关性
5. 在最终回答阶段引入多模态模型，对图片、表格等复杂内容进行综合理解

### 1.2、系统特点

#### （1）目标用户与具体应用场景

预期核心用户为在校大学生，典型场景：

1. **课后录音与课件联合复盘**：上传课堂 PPT、Word 材料、板书照片，构建课程知识库，辅助复盘与答疑
2. **期末冲刺与重点提问**：上传全套 PPT、实验讲义与辅导资料，系统保留标题结构、图片、表格、公式，支持针对性提问
3. **教学通知与杂项归档**：上传大纲、通知、截图等碎片资料，提取考核方式、作业要求、时间节点等

#### （2）产品特点

1. **解析优先**：文档质量首先由 MinerU 提供的结构化输出保证，不是粗暴切片后直接向量化
2. **自研 IR 中间格式**：不直接依赖 MinerU 原始 JSON，而是通过 IR 标准化层重建文档树
3. **文本检索主导，多模态问答增强**：检索阶段使用纯文本向量 + 关键词 + 重排序，回答阶段使用多模态模型
4. **高保真引用溯源**：支持 PDF 页坐标高亮，展示命中页码、块坐标、原图资产
5. **MinerU 格式监控**：内置严格格式审计系统，自动检测 MinerU API 输出格式变化

### 1.3、假定和约束

1. **开发约束**
   - 单人结合 AI 编程助手完成开发
   - 坚持 KISS 原则，不引入 LangChain 等重封装框架
   - 优先使用原生 SDK 与透明的数据流
2. **运行环境约束**
   - 项目作为本地 Web 应用交付，通过浏览器访问
   - 本地 Windows 笔记本运行，主要计算压力由云端 API 承担
3. **时间约束**
   - 课堂有效开发时间约 36 小时
   - 第一优先级是 MinerU 支持的文件类型：PDF、PPT、Word、图片
   - 音视频链路作为提升项，基础链路完成后接入
4. **项目定位约束**
   - 更关注核心链路是否跑通、关键体验是否可靠、技术路线是否自洽
   - 目标是"能演示、能解释、能回答项目问题"的 Mini 版系统

## 2、需求规定

### 2.1、软件功能说明

系统划分为九大模块。其中模块一至六为基础 RAG 链路（**已完成**），模块七至九为场景扩展模块（**数据库基础已就绪，前端页面待实现**）。

#### 模块一：多格式资料接入与异步解析

**已完成实现**：

支持文件类型：

- `pdf`、`ppt/pptx`、`doc/docx`、`png/jpg/jpeg`（统一通过 MinerU 在线 API 解析）

处理流程（16步 pipeline）：

1. `[A]` 申请 MinerU 批量预签名上传 URL
2. `[B]` PUT 上传文件到 OSS
3. `[C]` 轮询批量任务状态，获取 `full_zip_url`
4. `[D]` 下载 ZIP 包到本地 `data/mineru_zips/{doc_id}/`
5. `[E]` 解压 + bundle 文件角色识别（`bundle_parser.py`）
6. `[E+]` **MinerU 格式严格审计**（`format_checker.py`，输出到 `data/format_probe_log.jsonl`）
7. `[F]` 归一化：`content_list_v2.json` → `IRBlock[]`（`normalizer.py`）
8. `[G]` DOM 重建：section 树 + `header_path` 注入（`dom_builder.py`）
9. `[H]` 脚注关联（`footnote_linker.py`）
10. `[I]` 读取 `layout.json` 元数据（backend/version 信息）
11. `[J]` 写出 `document_ir.json`（`ir_writer.py`）
12. `[IR-V]` IR 结构校验（`ir_validator.py`）
13. `[K-vlm]` 多模态富化：图片描述 / 表格摘要（`enricher.py`，使用 `qwen-vl-plus`）
14. `[L]` Parent Chunk 构建（`parent_chunker.py`）
15. `[M]` Child Chunk 构建（`child_chunker.py`）
16. `[Chunk-V]` Chunk 结构校验 → `[N]` 向量化 → `[O]` Qdrant+SQLite 入库 → `[P]` JSONL 落盘 → `[K]` 更新文档状态

**待实现**：音视频转写（飞书妙记 / 通义听悟）

#### 模块二：MinerU 数据解析与标准化 IR

**已完成实现**：

双层模型架构（"宽进严出"）：

- **第一层（Raw）**：`models_raw_mineru.py`，`extra="allow"` 接收所有字段，未知字段触发 WARNING
- **第二层（IR）**：`models_ir.py`，严格 Pydantic 校验，枚举类型，坐标范围校验

Normalizer（`adapters/normalizer.py`）支持的块类型映射：

| MinerU Raw 类型 | IR BlockType | 备注 |
|----------------|--------------|------|
| `title` | `title` | |
| `paragraph` | `paragraph` | |
| `list`, `index` | `list` | `index`（目录）映射为 `list` |
| `image` | `image` | 含 VLM OCR 文本 |
| `chart` | `image` | 图表截图 + Markdown 数据，`AssetType=chart_image` |
| `table` | `table` | |
| `equation_interline` | `equation` | |
| `code` | `code` | |
| `page_header/footer/number/footnote` | 同名辅助块 | 不进入正文切片 |

Office 原生解析（DOCX/PPTX）特殊处理：
- 所有块 `bbox` 键**缺失**（非 null，是键不存在），使用 `[0,0,0,0]` 静默占位
- IR 校验器跳过 sentinel bbox 的坐标有效性校验
- 无 `origin.pdf`，前端隐藏"查看原文"按钮

落地输出：
- `data/rag_output/{doc_id}/document_ir.json`
- `data/rag_output/{doc_id}/document_ir_enriched.json`
- `data/rag_output/{doc_id}/parent_chunks.jsonl`
- `data/rag_output/{doc_id}/child_chunks.jsonl`

#### 模块三：结构感知切片与多模态富化

**已完成实现**：

**Parent Chunk 策略**（`parent_chunker.py`）：
- 每个 `IRSection` 对应一个 ParentChunk
- 跳过 synthetic root section（level=0）
- `text_for_generation` = 所有 main 块按 `order_in_doc` 排序拼接
- 图片/表格输出为 `"[图片: {caption}]"` 或 `"[表格: {caption}]"` 占位文本

**Child Chunk 策略**（`child_chunker.py`）：
- 原子块（`list/code/image/table/equation`）：整体作为一个 Child，不拆分
- `title` 块：整体作为一个 Child
- `paragraph` 块：滑动窗口切分（按中英文标点句子边界）
- 参数（`settings`）：`child_chunk_max_tokens=250`，`child_chunk_min_tokens=150`，`child_chunk_overlap_ratio=0.15`
- `embedding_text` 格式：`"{header_path_str}\n{text}"`（包含章节路径前缀）

**多模态富化**（`enrichers/enricher.py`）：
- 并发数：`_BATCH_CONCURRENCY=3`
- 图片：读取文件 → base64 → `qwen-vl-plus` 生成中文描述（100字以内）
- 表格：提取 HTML → `qwen-vl-plus` 生成中文摘要（100字以内）
- 富化结果写入 `embedding_text`，回流到 blocks 用于检索增强

#### 模块四：索引、入库与混合检索

**已完成实现**：

**向量索引**（`embedding_service.py`）：
- 模型：`text-embedding-v4`（阿里云百炼，1024 维）
- Child Chunk 文本向量化后存入 Qdrant，payload 含完整元数据

**关键词索引**（`database.py`）：
- SQLite FTS5 虚拟表 `child_chunks_fts`，`tokenize='unicode61'`
- 自动触发器：Child Chunk 插入/删除时同步更新 FTS5 索引

**混合检索**（`retrieval_service.py`）：
- 并行双路：向量召回（Qdrant cosine）+ 关键词召回（SQLite FTS5/BM25）
- RRF 融合（`k=60`）：`score(d) = Σ 1/(60 + rank_i(d))`
- 向量 limit=20，关键词 limit=20，融合后 top_k=15

**重排序**（`rerank_service.py`）：
- 模型：`qwen3-rerank`（DashScope 专有端点，不可切换 Provider）
- 对 top_k=15 结果二次打分，输出 top_n=5

#### 模块五：多模态问答与提示词编排

**已完成实现**：

**QA Service**（`services/qa_service.py`）：
- 系统提示词（`_SYSTEM_PROMPT`）：专业知识库问答助手，要求引用标注、忠实来源
- 上下文格式：`[来源{i}] {page_info} · {path_str}\n{retrieval_text}`
- 消息结构：`[system, user]` 两条，符合 OpenAI Chat 规范

**多 Provider 支持**：支持通过环境变量切换任意 OpenAI 兼容 Provider

| Provider | `QA_BASE_URL` | `QA_MODEL` |
|----------|--------------|------------|
| 阿里云百炼（默认） | 不填 | 不填（默认 `qwen-plus`） |
| DeepSeek Chat | `https://api.deepseek.com/v1` | `deepseek-chat` |
| DeepSeek 思维链 | `https://api.deepseek.com/v1` | `deepseek-reasoner` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o` |
| 月之暗面 | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |

**SSE 流式输出**：事件类型 `citations` → `thinking`（可选）→ `delta`（流） → `end`

**`enable_thinking` 说明**：
- 仅 `settings.qa_enable_thinking=True` 且模型支持时附加
- DeepSeek-reasoner：无需此参数，模型自动返回 `reasoning_content`
- 普通模型（qwen-plus/deepseek-chat/gpt-4o）：不支持，自动过滤

#### 模块六：前端交互与溯源展示

**已完成实现**：

**页面结构（React Router）**：
- `/` → `KnowledgeBasePage`：知识库首页（卡片网格，含创建/删除/类型选择）
- `/kb/:kbId` → `KBFilesPage`：文件管理页（上传/解析/删除/批量操作）
- `/kb/:kbId/chat` → `ChatPage`：对话问答页（SSE + 引用面板 + PDF bbox 高亮）
- `/tasks` → `TasksPage`：任务监控页
- `/settings` → `SettingsPage`：设置说明页
- `*` → 自动重定向到 `/`

**ChatPage 核心特性**：
- SSE 流式对话，`fetch + ReadableStream`（非 EventSource）
- 引用面板（右侧），展示每条来源的章节路径、页码范围、相关性分数
- 引用内容可展开/折叠查看原文片段

- Markdown 渲染：`react-markdown + remark-gfm`，自定义 `.md-prose` 样式（不依赖 `@tailwindcss/typography`）

**KBFilesPage 核心特性**：
- 拖拽上传、单文件上传、整文件夹上传（保留 `relative_path` 逻辑路径）
- 批量全选/取消选择，批量删除、批量重解析
- 文档状态轮询（`parsing` 状态时自动每 3 秒刷新）
- MinerU 警告展示（黄色 `⚠` 警告卡片，展示具体警告信息）
- 知识库名称/描述展示（`getKB()` 获取）

**暂未实现**：

- 文件夹删除 / 重命名 / 文件移动
- 按文件类型筛选

### 2.2、对功能的一般性规定

1. **异步任务**：文档解析、向量化、富化均为后台异步任务（`FastAPI BackgroundTasks`）
2. **可观测性**：前端实时展示任务状态（created/running/done/failed）；后端使用 `loguru` 记录关键步骤
3. **失败策略**：
   - MinerU 原始输出有未知字段 → 产生 WARNING（Raw层）
   - IR/Chunk 层不合法 → 阻止入库（Canonical层严格校验）
   - MinerU 降级/未知情况 → `documents.status=needs_review`，前端黄色警告
4. **引用一致性**：所有命中 chunk 可回溯到原文件、页码和坐标

### 2.3、用户界面

前端采用 React + Shadcn UI + Tailwind CSS 构建，是一个"知识库工作台"，而非单一聊天界面。

**已实现的信息架构**（五个页面）：

1. **知识库首页** (`/`)：卡片网格，支持创建（含类型选择 general/course）、删除、查看文件数
2. **文件管理页** (`/kb/:kbId`)：上传、解析触发、批量操作、状态监控、警告展示
3. **对话问答页** (`/kb/:kbId/chat`)：SSE 流式问答、引用面板、PDF 预览 + bbox 高亮
4. **任务中心** (`/tasks`)：查看所有后台任务状态、进度、错误信息
5. **设置页** (`/settings`)：API 配置说明、当前模型信息、服务健康状态

**布局**：左侧主导航（可折叠），主工作区，引用详情集成在 ChatPage 右侧

### 2.4、对性能的一般性规定

1. **质量优先**：混合召回 + 重排序 + 多模态推理，允许首响应略慢
2. **参考目标**：一般问题首字返回 3–6 秒，复杂多图/多表格问题可接受更长
3. **检索质量**：对标题、段落、图片说明、表格摘要具备较强召回能力

### 2.5、数据管理能力要求

| 层 | 路径 | 内容 |

- 图片/表格/公式资产 → 物理路径（`anchor_origin_pdf_path`）

## 3、运行环境规定

### 3.1、硬件设备

- 普通 Windows 笔记本电脑（开发与运行设备）

### 4.2、SQLite 数据库设计

数据库位于 `data/sqlite/mini_notebooklm.db`，包含 **11 张表**：

**核心业务表**（RAG 链路）：

### 4.4、MinerU 格式监控系统

这是本项目在 v1.0.0 基础版本之上新增的运维能力（2026-05-21 实现）。

**背景**：MinerU SaaS API 持续迭代，输出格式可能随时变化（已发现 `chart`、`index` 新块类型，`preproc_blocks` 新页面字段，DOCX Office 原生解析模式等）。

**双层架构**：

| 层 | 文件 | 策略 | 场景 |
|----|------|------|------|
| 宽松容错 | `adapters/normalizer.py` | 能用则用，未知字段 WARNING | 生产流水线，保证不中断 |
| 严格审计 | `adapters/format_checker.py` | 任何意外都记录，供运维排查 | 格式变更检测 |

**`format_checker.py` 设计**：
- `KNOWN_BLOCK_TYPES`、`BLOCK_KNOWN_FIELDS`、`CONTENT_KNOWN_FIELDS` 等完整规范常量（唯一事实来源）
- `Deviation` dataclass：`severity(error/warning/info)`, `location`, `issue`, `detail`
- `FormatCheckReport` dataclass：统计偏差数量、块类型分布、ZIP 文件清单
- `check_bundle(zip_root, source_filename, doc_id)` → `FormatCheckReport`
- `log_report_to_file(report, log_path)` → 仅有偏差时追加到 JSONL 日志

**流水线集成**（`pipeline_service.py` 步骤 [E+]）：
- 每次正式文档解析后，在归一化前自动运行格式检查
- 有偏差 → 追加到 `data/format_probe_log.jsonl`，记录 WARNING 日志
- 格式完全符合 → INFO 日志，不写文件
- **不影响后续流水线**，探针只审计不拦截

**独立探针脚本**（`tools/mineru_format_probe.py`）：
```bash
cd backend

# 日常检查（扫描已有解析结果，不消耗 API 配额）
uv run python tools/mineru_format_probe.py

# 实时上传测试文件检查（消耗 MinerU API 配额）
uv run python tools/mineru_format_probe.py --online

# 退出码：0=clean, 1=errors, 2=warnings, 3=info（可接入 CI）
```

**验证结果**（2026-05-21）：7/7 文档（PDF×5 + DOCX×1 + PPTX×1）全部 ✅ 格式完全符合预期。

### 4.6、前端关键技术点

**SSE 流式解析**（`client.ts: streamChat`）：
- 使用 `fetch + ReadableStream`（非 `EventSource`），支持 `AbortController` 取消
- 逐行解析 `data: {...}` 格式，支持 `citations/delta/thinking/end/error` 五种事件

**PDF bbox 高亮**（`ChatPage.tsx`）：
- 使用 `react-pdf` 的 `Document + Page` 组件渲染 PDF
- 在 Page 容器上叠加绝对定位的 `<div>` 实现高亮框
- `bbox_norm1000` 坐标（0–1000）换算为页面百分比：`x / 1000 * 100 + "%"`

**Markdown 渲染**（`index.css: .md-prose`）：
- 不依赖 `@tailwindcss/typography` 插件（Tailwind v4 的 preflight 会重置列表样式）
- 自定义 `.md-prose` 类手动恢复 `ul/ol` 缩进、`li` 列表符号、`code` 块背景等

## 6、结论

本项目的技术路线：

1. **专业解析优先**：用 MinerU 把复杂资料高质量结构化（不是粗暴切片）
2. **自研 IR 中间层**：重建文档结构、注入标题路径、保留坐标锚点（不直接依赖 MinerU 原始 JSON）
3. **纯文本向量 + 关键词混合检索**：两路并行召回，RRF 融合
4. **重排序提质**：`qwen3-rerank` 对召回结果二次打分
5. **多模态旗舰模型回答**：最终回答阶段综合理解图片、表格与正文
6. **格式监控**：内置严格审计系统，自动检测 MinerU API 格式变化

这条路线符合当前模型能力现状，在有限开发时长内完成了一个效果可靠、逻辑完整、适合课程展示的 AI 知识库系统。
