# 题目：面向大学生的多模态课程知识库与 AI 辅导系统（Mini-NotebookLM）

## 1、任务概述

### 1.1、目标

本项目旨在开发一款**面向大学生的多模态课程知识库与 AI 辅导系统（Mini-NotebookLM）**。

当前主流 AI 知识库产品（如 Google NotebookLM、腾讯 ima 等）均定位于通用个人知识库，对大学生课程学习场景缺乏专项支持——若要用于课后复习、考前备考等特定任务，上手门槛较高，体验割裂。本项目针对这一空白，聚焦大学生课程学习场景，提供一键式、场景化的 AI 辅导体验，同时保留通用个人 AI 知识库的完整能力。

系统核心由两部分组成：

1. **通用多模态 AI 知识库底座**：支持 PDF、PPT、Word、图片等多格式资料的高质量解析、结构化切片、向量与关键词混合检索、多模态问答与溯源展示，具备比肩一线大厂同类产品的技术效果。v1.2.0 起增加"本地文件夹绑定模式"，并原生支持 `.txt`（课堂录音转写） / `.md`（生成的讲义、用户笔记）两种文本类型。
2. **场景 AI Agent 模块**：在知识库底座之上，针对课后复习、课程信息整理两个核心痛点，提供具备多轮对话与对话分叉能力的 AI Agent 辅学功能（v1.2.0 本期实现）；AI 出卷判分作为提升项保留至未来迭代。

系统采用现代前后端分离架构，在本地 Windows 环境中运行，核心解析、向量化、重排序与问答能力依托云端 API。

本项目技术路线的核心思路是：

1. 先用专业解析服务（MinerU）把复杂资料高保真地结构化
2. 再由自研系统重建文档层级、标准化中间格式并进行结构感知切片
3. 使用向量检索与 BM25 关键词检索双路混合召回
4. 增加重排序环节提升相关性
5. 在最终回答阶段引入多模态旗舰模型，综合理解图片、表格、公式等复杂内容
6. 在知识库底座之上，通过 AI Agent 流程实现课后复习引导、智能组卷、答卷判分等垂直场景功能

### 1.2、系统（或用户）的特点

#### （1）目标用户与典型使用场景

预期核心用户为在校大学生，三大典型使用场景如下：

**场景一：AI 伴学·高效复盘（课后复习，v1.2.0 本期实现）**

痛点：传统课后复习耗时低效，知识点散乱难以系统梳理；课堂录音转写出来的文本动辄数万字，自己读完也未必能消化。

学生将本课程的资料组织成约定目录结构后，把课程知识库绑定到该本地文件夹。每次课后只需点几下：选日期 → AI 在同一会话上下文中逐节生成"老师口吻"的详细讲义并自动存盘 → 学生在同一对话中追问、对任意点 fork 出独立的探究分支、可手动开关思维链；所有生成结果以 `.md` 文件持久化到磁盘，可被任意编辑器编辑、复用、检索。

价值：把动辄数万字的录音转写文本，转化为可问可答可分叉的"活讲义"；学习档案完全归学生本地拥有。

**场景二：AI 考官·靶向出题（提升项，本期不交付）**

留作未来迭代方向：用户整理 Markdown 题库 → AI 智能组卷（含知识点覆盖、数值变形）→ 答卷拍照后 **MinerU 解析 + LLM 逐题对照判分**。本期暂不实现，待基础场景稳定后再做。

**场景三：AI 管家·日程提醒（课程信息卡片，v1.2.0 本期实现）**

痛点：教务通知繁杂易漏，时间节点分散难以统一管理。

学生在课程 KB 绑定文件夹中放入教学大纲、课程通知截图、评分标准等资料并触发解析后，进入"课程管家"页面 → 系统用 5 个固定查询触发混合检索 → LLM 一次结构化抽取考核方式 / 作业 DL / 考试时间 / 老师联系方式 / 重要通知 → 卡片形式展示，并在课程 KB 内任何页面顶部以黄色 banner 提醒 7 天内的截止日。卡片内容可基于多轮对话基座进一步追问。

价值：提取关键信息，生成备忘，避免因信息遗漏造成成绩损失。

**通用场景**：
- 上传任意资料组建个人知识库，进行自由问答与信息检索
- 围绕某一章节、某张图表、某个公式精准提问
- 查看检索来源溯源，定位到原始文档页码与坐标

#### （2）产品优势与特点

1. **垂直领域先发优势**：专门针对大学生课程学习场景做一键式、傻瓜式设计，显著低于通用知识库的上手门槛，填补目前大厂在该细分场景的空白。
2. **技术链路完整、效果不弱于大厂**：
   - MinerU 高保真文档解析，完整保留文档层级结构
   - 自研 IR 标准化中间层，重建文档树与坐标锚点
   - 父子切片（Parent/Child Chunking）结合语义边界保留
   - 向量检索 + BM25 关键词检索双路混合召回
   - 重排序二次精排，提升相关性
   - 多模态旗舰模型综合理解图片、表格、公式
3. **AI Agent 能力**：三个场景模块均涉及多步骤串联操作（上传→解析→生成→交互→保存），具备多轮操作的 AI Agent 特征，而非单轮问答。
4. **通用能力保留**：在垂直场景之外，系统同样支持作为通用个人 AI 知识库使用。

### 1.3、假定和约束

1. **开发约束**
   - 单人结合 AI 编程助手完成开发
   - 坚持 KISS 原则，不引入 LangChain 等重封装框架
   - 优先使用原生 SDK 与透明的数据流

2. **运行环境约束**
   - 项目作为本地 Web 应用交付，通过浏览器访问
   - 不做桌面打包，核心计算压力由云端 API 承担

3. **时间约束**
   - 有效开发时间约 36 小时（课堂），课外自主开发不限
   - 第一优先级是 MinerU 支持的基础文件类型：PDF、PPT、Word、图片
   - 音视频转写链路作为提升项，在基础链路完成后接入

4. **项目定位约束**
   - 核心链路跑通、关键体验可靠、技术路线自洽是基本标准
   - 场景模块的关键体验（复习引导质量、模拟卷合理性、信息提取准确率）是核心验收标准
   - 目标是做出一个能演示、能解释、有真实使用价值的系统

#### 模块一：多格式资料接入与异步解析模块

该模块负责把用户上传的原始资料转成后续知识库可处理的中间结果，并支持"本地文件夹绑定"作为课程知识库的资料来源。

支持范围：

1. 文档与图片类
   - `pdf`、`ppt/pptx`、`doc/docx`、`png/jpg/jpeg`
   - 统一通过 MinerU 在线 API 解析
2. 纯文本类（v1.2.0 新增）
   - `txt`：课堂录音转写文本
   - `md`：AI 生成或用户手写的笔记
   - **跳过 MinerU 解析**，直接以 UTF-8 文本读取
3. 音视频类（提升项）
   - `mp3/wav/m4a/mp4` 等
   - 通过飞书妙记或通义听悟转写为带说话人与时间戳的文本文件
   - 视频关键帧抽取作为后期接入项

**资料接入两种模式**：

- **上传模式**（v1.0.0 起）：用户从浏览器逐个或批量上传文件至 KB
- **文件夹绑定模式**（v1.2.0 新增，课程 KB 必用）：用户在创建 KB 时填写本地目录绝对路径，系统通过"同步"按钮扫描该目录登记文件；文件夹内文件变更后再次同步即可。约定目录结构见模块七。

文件夹绑定模式的关键设计点：
- 不自动调用 MinerU（节省 API 配额）；用户在文件管理页点"解析"按钮按需触发
- 已消失的文件 status 标为 `missing`（不立即删 DB 记录，由用户确认）
- `.txt/.md` 文件 status 直接为 `text_only`，跳过整个 MinerU 流水线

处理要求：

1. 对文档与图片资料（pdf/ppt/docx/图片）
   - 后端上传或读取本地文件 → MinerU 在线 API → 获取 `full_zip_url`
   - 下载并解析返回压缩包
   - 识别 `content_list_v2.json`、`layout.json`、`*_origin.pdf`、`images/*`
2. 对纯文本资料（txt/md）
   - 直接登记到 documents 表，不进解析流水线
   - 由场景模块（模块七）按需读取原文
3. 对音视频资料（提升项）
   - 获取说话人分段、时间戳与正文文本
   - 输出为知识库可消费的标准文本格式

#### 模块二：MinerU 返回数据解析与标准化 IR 模块

这是系统的核心中间层，负责将 MinerU 原始输出标准化为自研 IR（中间表示）格式，而非直接将原始结果喂给向量库。

处理流程：

1. 以 `content_list_v2.json` 为主输入，以 `layout.json` 提供页面尺寸与绝对坐标补充
2. 重建文档 DOM 层级树
3. 为每个正文块注入 `header_path`（标题面包屑路径）
4. 提取页眉、页脚、页码、脚注
5. 将图片、表格、公式、代码、列表等多模态对象统一建模
6. 结合 `*_origin.pdf` 保存可供前端高亮的页坐标锚点

标准化输出：

- `document_ir.json`：基础标准化中间格式，记录文档页信息、section 树、块信息、标题路径、坐标锚点、多模态资产关系
- `document_ir_enriched.json`：在基础 IR 上增加图片描述、表格摘要、上下文补充等富化结果
- `parent_chunks.jsonl`：按小节组织的大粒度块，用于回答阶段回填完整上下文
- `child_chunks.jsonl`：面向向量检索的小粒度块，用于召回、重排序与精确定位

该模块遵循以下规范：

1. 原始 MinerU 输出层允许有限兼容
2. 自研 IR 与 Chunk 层必须严格校验
3. 若结构不符合要求，必须明确报错，不将脏数据写入知识库

#### 模块三：结构感知切片与多模态富化模块

该模块将标准化 IR 转成适合检索的块。

关键要求：

1. 切片不能跨越 H1/H2 等逻辑边界
2. `list` 与 `code` 作为原子块整体保留
3. 文本段落采用 Parent/Child 双层切片：Child 用于向量检索，Parent 用于回答阶段补全上下文
4. 图片、表格、公式采用"文本代理 + 原始资产保留"的双轨策略

多模态富化策略：

1. **图片**：提取标题、周边段落与资产路径；调用 Qwen-VL 视觉模型（型号通过 `VLM_MODEL` 环境变量配置，默认采用阿里云百炼当前推荐的视觉多模态模型）生成图像描述；检索时使用文本代理向量化，回答时透传原图给最终模型
2. **表格**：优先对 MinerU 返回的 `html` 做轻量结构清洗（提取表头、首列、行列数、关键单元格文本）；再调用 Qwen-VL 视觉模型生成表格摘要；若仅有截图则直接进行视觉理解；检索时使用摘要文本而非原始 HTML
3. **行间公式**：优先使用 LaTeX 文本，同时保留公式截图路径用于展示

---

#### 模块四：索引、入库与混合检索模块

检索架构采用"向量 + 关键词双路混合 + 重排序"方案：

1. **纯文本向量化**：使用阿里云百炼 `text-embedding-v4`，只对文本代理内容做向量化
2. **关键词检索**：对正文、标题、图片描述、表格摘要建立关键词索引，用于补足稀有术语与短查询场景
3. **混合召回**：向量召回 + 关键词召回并行进行，使用融合策略合并候选结果
4. **重排序**：对召回结果使用 `qwen3-rerank` 进行二次打分，提升最终相关性

本地数据底座：

- **Qdrant**：存储 Child Chunk 向量与 metadata
- **SQLite**：存储文档记录、文件路径、任务状态、Parent/Child 映射、资产索引，结合 FTS5 实现本地全文检索/BM25
- **文件系统**：存储原始上传文件、MinerU zip、`origin.pdf`、`images/*`、IR JSON、Chunk JSONL

#### 模块五：多模态问答与提示词编排模块

该模块负责把检索结果组织为最终可用的问答上下文。

通用问答流程：

1. 用户发起问题，系统做标准化与必要的查询改写
2. 执行混合召回 → `qwen3-rerank` 重排序
3. Child 映射回 Parent，整合标题路径、正文、图片描述、表格摘要、页码与原始图片路径
4. 调用 Qwen 通用大语言模型（型号通过 `QA_MODEL` 环境变量配置，且支持 OpenAI 兼容协议下任意 Provider 切换）进行最终问答

最终回答支持：图文混合理解、引用原始文档页码与图片、结合表格截图回答、命中内容高亮溯源。

**场景专项提示词**：针对课后复习引导、试卷生成、答卷判分、信息提取等任务，提供专项提示词模板，而非与通用问答共用同一套 Prompt。

#### 模块六：前端交互与溯源展示模块

前端采用 `React + Shadcn UI + Tailwind CSS` 构建，设计为"知识库工作台"，而非单一聊天页面。

基础功能：

1. 知识库空间管理：新建、重命名、删除知识库，按课程/通用分类

3. 解析状态查看：排队中、解析中、切片中、向量化中、完成、失败
4. 对话式问答：SSE 流式输出、Markdown/公式/图片引用渲染

#### 模块七：AI 伴学·课后复盘与问答模块

**功能定位**：大学生课后复习的 AI 私教，基于课堂录音转写文本自动生成"老师口吻"的逐节课堂讲义，并在同一对话上下文中支持后续多轮答疑与对话分叉。

**前置约定（课程知识库目录结构）**：

课程知识库以"绑定本地文件夹"的方式工作（不再是逐文件上传），约定根目录下：

```
<课程名称>/
  课堂录音/
    <YYMMDD>/                         ← 日期目录
      <课程>YYMMDD第NN节.txt          ← 录音转写（每小节一份）
      <课程>YYMMDD第NN节课堂要点.md   ← AI 生成的复习讲义（保存后自动出现）
  课件/    *.ppt(x) 等               ← 模块九检索用
  作业/    *
  通知/    *
```

`.txt` 与 `.md` 文件不进 MinerU 解析链路（节省 API 配额），由模块七直接以纯文本读取。

**功能流程**：

1. 学生进入课程知识库 → 二级侧边栏点"课后复习" → 选日期
2. 后端读取该日期目录下所有 `*.txt`，按"第 N 节"排序
3. **同一对话内逐节生成讲义**：以可配置提示词（首节模板 + 后续节模板）逐节调用 LLM，所有节次共享同一 conversation 上下文，输出三份独立的"课堂要点"
4. 学生点"保存到本地" → 写入对应 `<课程>YYMMDD第NN节课堂要点.md`
5. 学生在同一会话内继续追问（多轮对话），上下文完整保留
6. 学生可对任意 assistant 消息执行 **fork**（分叉新会话），不同问题不会污染主线
7. 学生可手动开关 **思维链** 模式；思考过程与回答均流式输出
8. 历史讲义可重新加载展示，并继续在原 conversation 内追问

**AI Agent 特征**：多轮对话（非单轮问答）、跨节次上下文一致性、对话分叉树、思维链可开关、生成结果回写磁盘形成可追溯学习档案。

**前端入口**：`/kb/:kbId/review`，三栏布局（会话列表 / 聊天主区 / 上下文面板）。

**配套加分功能**：基于讲义生成自测题、关键概念抽取、章节内 TOC 跳转、导出 PDF（浏览器打印）。

#### 模块八：AI 考官·期末冲刺与评卷系统（提升项，本期不实现）

> **本期范围说明**：模块八与音视频转写一并列入"未来提升项"，v1.2.0 不交付。以下设计作为未来实现的方向参考保留。

**功能定位**：从用户整理的 Markdown 题库中智能组卷、AI 判分、识别知识漏洞，为大学生考前备考提供针对性辅助。

**子流程一：题库构建（用户手工 + AI 辅助）**

1. 用户自行整理 Markdown 格式题库，存到 `<课程 KB>/题库/<题型>/*.md`
2. 系统读取 .md 文件，AI 辅助打知识点标签 + 难度分级
3. 入库到 `exam_questions` 表

**子流程二：智能组卷**

1. 学生指定课程 KB + 出题参数（题型分布、难度、题量、重点章节）
2. AI 按知识点覆盖度筛选题目，并对部分题做数值/形式变形（避免照搬）
3. 输出 Markdown 试卷（可打印，不含答案版）
4. 题目避免含图；表格/公式用 Markdown 原生表达

**子流程三：答卷判分**

1. 学生将纸上答案拍照上传
2. **使用 MinerU 解析答卷图片**（不使用 VLM 直读 —— 对正式文字与公式 MinerU 更稳）
3. 得到 Markdown → LLM 与标准答案逐题对照（**逐题独立判分**，不一次性整卷判分以保证质量）
4. 给出总分、逐题点评、知识漏洞分析、复习建议

**前端入口**：独立 `/kb/:kbId/exam` 页面（题库管理 / 组卷向导 / 答卷上传 / 判分报告四个子页）。

#### 模块九：AI 管家·日程与通知防呆模块

**功能定位**：从课程 KB 已绑定文件夹中的通知、教学大纲、评分标准等资料中自动抽取关键信息，生成结构化课程信息卡片，并在系统内给出截止日临近的防遗漏提示。

**功能流程**：

1. 学生进入课程知识库 → 二级侧边栏点"课程管家"
2. 后端用 5 个固定查询触发现有混合检索：
   - 考核方式 / 评分标准 / 成绩比例
   - 作业要求 / 截止时间 / 提交方式
   - 考试时间 / 期中 / 期末
   - 老师 / 联系方式 / 答疑时间
   - 重要通知 / 注意事项
3. 汇总检索结果 → LLM **一次结构化抽取**（JSON 输出 schema 见 §详细实施手册）→ 写入 `course_info_cards` 表
4. 前端展示卡片：考核占比 / 截止日时间线 / 老师信息 / 重要通知（Markdown）
5. 学生可基于卡片在同一 KB 上下文中追问（复用模块七的多轮对话基座）
6. 进入课程 KB 时：若未来 7 天内有 deadline → 顶部黄色 banner 提醒

**AI Agent 特征**：单次结构化抽取 + 多轮追问；非多步 Agent 编排（一次 LLM 调用即可完成抽取，无需复杂工作流）。

**前端入口**：`/kb/:kbId/info`，含卡片网格 + 重新生成按钮 + 追问聊天面板。

### 2.2、对功能的一般性规定

1. **异步任务与重试**
   - 文档解析、向量化、富化、题库解析、答卷识别均视为异步任务
   - 对外部 API 调用可做有限次重试，失败后给出明确错误信息
2. **可观测性**
   - 前端可查看任务状态：排队中、解析中、切片中、向量化中、完成、失败
   - 后端保留错误日志与关键步骤日志
3. **失败策略**
   - 若原始数据不符合预期，可尝试兼容降级
   - 若 MinerU 原始输出出现未知字段，至少产生 warning 并保留原始字段
   - 若进入 IR/Chunk 层仍不合法，必须报错并阻止入库
4. **文档引用一致性**
   - 任何进入检索和回答链路的块，必须可以回溯到原文件、页码和坐标或时间戳
5. **场景模块数据隔离**
   - 题库数据、复习笔记、课程信息卡片等场景层数据，应与通用知识库数据在逻辑上区分，避免相互污染

### 2.3、用户界面

前端采用 `React + Shadcn UI + Tailwind CSS` 构建，整体设计为"知识库工作台 + 场景模块入口"的多页面结构。

**推荐前端信息架构**：

1. **知识库首页**：展示已有知识库，支持新建、重命名、删除，标注知识库类型（课程/通用），课程知识库自动展示三个场景模块快捷入口
2. **知识库文件管理页**：网盘式界面，支持目录树浏览、文件上传（单文件/文件夹）、批量操作、解析状态查看、按文件类型筛选
3. **对话问答页**：对话式问答，支持 Markdown、公式、图片引用渲染，SSE 流式输出，引用来源展示
4. **来源详情页 / 预览页**：文档基本信息、标题结构、命中片段、页码、图片资产；可预览 `origin.pdf`，支持根据 `bbox_page` 高亮定位
5. **任务中心**：查看解析、切片、向量化、入库等后台任务状态与错误原因
6. **课后复习界面**（课程知识库内子页面）：资料范围选择、引导式复习对话、复习笔记生成与保存
7. **模拟测试页面**（独立页面）：题库管理、出题设置、试卷预览与打印、答卷上传、判分报告
8. **课程管家界面**（课程知识库内子页面）：碎片资料上传、课程信息卡片展示、截止日提醒预警、问答交互、导出功能

**布局结构**：

1. 左侧主导航栏：支持收起/展开，提供知识库列表、任务中心、设置入口
2. 二级侧边栏：知识库内目录树、筛选器、场景模块快捷入口，支持收起/展开
3. 主工作区：根据当前页面显示文件管理、聊天、预览、场景模块或任务内容
4. 右侧详情面板：可选展示命中来源、页码、缩略图、表格预览、块级信息，支持按需展开/收起

**界面概念草图说明**（文字描述）：

知识库首页为卡片式布局，每张卡片显示知识库名称、类型标签（课程/通用）、文件数量、最近更新时间。课程类知识库卡片底部附两个本期快捷入口按钮（**课后复习、课程管家**）；进入课程 KB 后由二级侧边栏统一切换"文件管理 / 通用对话 / 课后复习 / 课程管家"。对话问答页采用左右分栏布局，左侧为对话区，右侧为可折叠的来源溯源面板，支持 PDF 内联预览与段落高亮。课后复习页采用三栏布局（会话列表 / 聊天主区 / 元信息面板）。

### 2.4、对性能的一般性规定

1. **质量优先于极限低延迟**：系统目标是保证问答准确率与可解释性，因存在混合召回、重排序和多模态推理，允许首响应略慢于极简系统
2. **通用问答**：一般问题首字返回时间控制在 `3-6 秒`；复杂多图、多表格问题可接受更长响应时间
3. **场景模块**：
   - 课后复习首节首字返回：`5-10 秒`（之后逐节流式生成，单节生成总时长 `30-90 秒`，含思维链时更长）
   - 课程信息卡片生成（含 5 次检索 + 1 次结构化抽取）：`10-30 秒`
   - 组卷生成 / 答卷判分（提升项）：本期不实现
4. **并发访问量**：本项目为本地单用户部署，设计目标为同时支持 ≤3 个活跃浏览器标签页，后端并发 API 调用 ≤5 个；不考虑多用户并发场景
5. **支持设备**：运行于 Windows 10/11 本地环境，前端支持 Chrome 120+、Edge 120+，不要求移动端兼容
6. **数据存储规模**：
   - 单知识库上传资料总量预估 ≤1 GB
   - Qdrant 向量记录数量预估 ≤50 万条（约 100 份长文档全量切片后的规模）
   - SQLite 数据库文件预估 ≤500 MB
   - 文件系统（原始文件 + MinerU zip + 图片资产）预估总占用 ≤10 GB

### 2.5、数据管理能力要求

本项目采用"文件系统 + SQLite + Qdrant"的分层存储结构：

1. **文件系统**
   - 原始上传文件、MinerU 返回 zip、`origin.pdf`、`images/*`、IR JSON、Chunk JSONL
   - **课程 KB 绑定的本地文件夹**（v1.2.0）：含课堂录音 .txt、AI 生成的课堂要点 .md
   - 提示词模板目录 `backend/app/prompts/*.md`（v1.2.0）

2. **SQLite**
   - `knowledge_bases`：含 `bound_folder_path` 字段（v1.2.0）
   - `documents`：含 `bound_file_path` / `folder_category` 字段（v1.2.0）
   - `parent_chunks` / `child_chunks`：Parent/Child 映射关系，FTS5 索引
   - `assets`：图片/表格/公式资产索引
   - **`conversations`** （v1.2.0）：多轮会话元信息（kb_id, scenario, parent_conversation_id, fork_from_message_id, enable_thinking）
   - **`messages`** （v1.2.0）：会话消息（role, content, thinking, sequence_num, citations, metadata）
   - `course_info_cards`：课程信息卡片，含 `deadlines_normalized` JSON（v1.2.0）
   - `review_notes` / `exam_questions` / `exam_papers` / `exam_submissions`：表已就绪但本期不使用（review 笔记落磁盘文件、exam 系列为提升项）

3. **Qdrant**
   - Child Chunk 向量与 metadata（不引入 `scene_type` 字段；三个场景共享同一检索结果）

**数据映射要求**：

1. 任何向量记录必须能映射回对应 Child Chunk
2. 任何 Child Chunk 必须能映射回 Parent Chunk 与原始文档页码
3. 任何图片/表格/公式资产必须可回溯到物理路径
4. 任何会话消息可回溯到 conversation；fork 会话保留 parent 链接
5. 课后复习生成的讲义文件以绑定文件夹中的 `*.md` 形式持久化，可被外部编辑器编辑

**故障处理方案**：

| 故障类型 | 现象 | 应对方案 |
|---|---|---|
| MinerU API 返回异常 | 解析任务报错或超时 | 重试 3 次，失败后标记任务状态为"失败"，前端展示错误原因，已有数据不受影响 |
| Qdrant 服务不可用 | 检索请求超时 | 降级为纯 SQLite FTS5 关键词检索，禁用向量召回，给出提示 |
| 大模型 API 限流或超时 | 问答请求超时 | 重试 2 次，返回错误提示，不影响已入库数据 |
| 磁盘空间不足 | 文件写入失败 | 在上传时检查可用磁盘空间，低于 500 MB 时拒绝上传并给出提示 |
| 解析数据格式不合法 | IR/Chunk 层校验失败 | 阻止脏数据入库，标记任务失败，原始文件保留，用户可重新触发解析 |
| 绑定文件夹路径不存在或无权限 | 同步报错 | 接口返回明确错误；前端展示错误信息，建议用户检查路径 |
| .txt 文件编码异常 | 模块七读出乱码 | 用 chardet 探测编码，失败时回退 `errors="replace"` 并提示用户 |
| LLM 返回 JSON 不合法（课程管家） | 卡片抽取失败 | 重试 1 次更严格提示词；二次失败时把原始回答存到 important_notes，由用户手动整理 |

### 2.6、关于合规开源组件使用与原创声明（必填项）

1. **合规组件接入声明**
   - 文档与图片解析：MinerU 官方在线 API
   - 音视频解析：飞书妙记或通义听悟 API（提升项）
   - 前端框架：React、Vite、Shadcn UI、Tailwind CSS

2. **核心智能引擎大模型**

   - 文本重排序模型：阿里云百炼 `qwen3-rerank`
   - 视觉多模态模型：阿里云百炼 Qwen-VL 系列最新模型（通过 `VLM_MODEL` 环境变量指定具体型号）
   - 最终问答模型：Qwen 通用大语言模型（通过 `QA_MODEL` 环境变量指定具体型号；支持切换到 DeepSeek/OpenAI 等任意 OpenAI 兼容 Provider）

3. **自研部分**
   - MinerU 返回压缩包解析逻辑
   - 标准化 IR 中间格式与文档 DOM 重建
   - 结构感知切片（Parent/Child Chunking）
   - 混合检索融合策略与提示词编排逻辑
   - 高亮溯源展示逻辑
   - AI 课后复习引导流程与笔记生成逻辑
   - 题库结构化提取与智能组卷算法
   - 答卷识别、判分与知识漏洞分析逻辑
   - 课程信息碎片化提取与结构化输出逻辑
   - 场景专项提示词模板体系

### 3.4、接口协议

| 接口类型 | 协议 | 说明 |
|---------|------|------|
| 前端 ↔ 后端（普通请求） | HTTP/1.1 REST | JSON 格式，前端通过 `localhost:8000` 访问 FastAPI |

| 后端 ↔ Qdrant | HTTP/1.1 | 向量写入与检索，默认 `localhost:6333` |
| 后端 ↔ SQLite | 本地文件 I/O | 直接读写本地 `.db` 文件，无网络通信 |

### 4.2、风险管理

#### 风险一：DOM 树重组与父子切片算法受阻（高风险）

**难点剖析**：基于 MinerU 输出的 JSON，自主开发还原多层级 DOM 结构树的算法较为复杂——需正确识别标题层级、注入 `header_path` 面包屑、处理跨页断行与边缘情况，难度较高。

**触发条件**：第 3-4 次课结束后，`document_ir.json` 仍无法正确重建文档层级结构。

**应对预案**：
- 降级为固定字数机械切片（512 token，滑动窗口 50 token），保障基本检索功能可用
- 放弃坐标锚点，改为仅记录页码用于文本引用
- 核心问答链路依然完整，仅损失结构感知与精准溯源能力

---

#### 风险二：多模态图表资产异步摘要链路过长（中高风险）

**难点剖析**：系统提取出原始图片后，需送入 Qwen-VL 视觉模型生成摘要，再进行向量化入库，链路步骤多、依赖多个异步任务串联，开发与调试难度大，且摘要质量不稳定。

**触发条件**：第 5-6 次课结束后，图片/表格的摘要生成与向量化链路仍无法稳定运行。

**应对预案**：
- 砍掉图片与表格的向量化，降级为纯文本 RAG 模式
- 图片与表格仅保留原始资产路径，在回答阶段透传给最终模型直接理解，不参与检索
- 问答效果略有下降但系统整体可用，检索准确性影响可接受

---

#### 风险三：前端 PDF 渲染与坐标高亮门槛较高（中风险）

**难点剖析**：前端要实现"PDF 动态绘制画布 → 聊天框点击 → 平滑滚动翻页 → 绝对坐标绘制半透明高亮框"，这一套 UI 交互的工程难度对本科实训而言较高，需处理 PDF.js 渲染、坐标系转换、异步滚动等多个技术问题。

**触发条件**：第 9-10 次课中，PDF 高亮溯源功能实现耗时超出预期，影响其他前端模块进度。

**应对预案**：
- 砍掉动态高亮功能，改为静态图文展示模式（命中段落以文本卡片展示，附页码与截图缩略图）
- 保留命中来源展示、页码标注、原图资产预览等核心溯源能力
- 用户体验略有下降，核心问答与场景功能不受影响

---

#### 风险四：v1.2.0 场景模块开发时间不足（中风险）

**触发条件**：v1.2.0 开发已开始但模块七的多轮对话基座或 fork/思维链等关键交互未跑通。

**应对预案（优先级砍功能）**：

| 优先级 | 保留 | 可砍 |
|--------|------|------|
| P0 | 通用知识库基座（v1.1.0） + 文件夹绑定 + 模块七基础（逐节生成 + 单轮追问 + 存盘） + 模块九基础（卡片生成 + DL banner） | — |
| P1 | 模块七 fork 分叉 + 思维链开关 + 模块九卡片追问 | fork UI 可降级为"复制会话" |
| P2 | 自测题 / 关键概念抽取 / 章节内 TOC / 导出 PDF 等加分项 | 全部可去 |

若 P0 也无法完成，则模块七仅交付"逐节生成 + 存盘"（无追问），模块九交付"卡片展示"（无追问）。

## 5、结论

本项目从两个维度形成差异化优势：

**技术维度**：采用 MinerU 高保真文档解析、自研 IR 标准化中间层、父子切片、向量与 BM25 双路混合检索、重排序、多模态旗舰模型问答的完整技术链路，在效果上不弱于同类商业产品。

**产品维度**：聚焦大学生课程学习这一目前主流 AI 知识库产品尚未专项覆盖的细分场景。v1.2.0 通过"AI 伴学·课后复习"（同一会话内逐节生成讲义 + 多轮追问 + 对话分叉 + 思维链流式）与"AI 管家·课程信息卡片"（单次结构化抽取 + 截止日防呆），将多模态知识库能力转化为大学生开箱即用的日常辅导工具。模块八（AI 考官）作为未来提升项，待基础能力稳定后再行迭代。

两者相辅相成：完整的技术链路保障了系统效果的下限，专注的场景化设计则决定了系统的实用价值与差异化定位。
