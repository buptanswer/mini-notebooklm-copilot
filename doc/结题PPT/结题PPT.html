01 / Background选题背景与任务目标

为什么做它 —— 大学生课程场景的空白

!痛点

  • 主流 AI 知识库（NotebookLM、腾讯 ima）都定位「通用个人知识库」
  • 并没有为大学生课程学习场景专门设计
  • 课后复习、考前备考、教务信息整理是高频刚需，通用工具上手门槛高、体验割裂

→我的任务目标

  • 做一个本地化的两层系统
  • 下层：通用多模态知识库底座，效果对标一线大厂
  • 上层：面向大学生的场景 AI Agent 辅学
立项验收标准：核心链路跑通 · 关键体验可靠 · 技术路线自洽 · 能演示、能解释、有真实价值

难点 ① / Hard ProblemMinerU 解析 → 自研 IR 标准化

把「扁平、会漂移」的解析，重建成结构化文档

!真实的坑（不是想象的）

  • 输出扁平：标题层级永远 = 1，拿不到章节树
  • 格式会漂移：字段增删、同名字段语义变
  • Office 文档无坐标、无 origin.pdf
  • 跨页拆分块、跨页表格「空幽灵块」污染检索

✓自研解法

  • 双层「宽进严出」IR：脏数据绝不入库
  • LLM 文档树重建：理解标题语义、注入面包屑
  • 坐标锚点：Office 自动 OCR 转 PDF 拿 bbox
  • 格式漂移监控：19 项语义校验，以实测为准

难点 ② / Hard Problem结构感知父子切片 + 多模态富化

切得准，才检索得准；多模态分轨处理

⛓父子切片 · Small-to-Big

  • 父块：按 N 级标题聚合，语义连贯，补全上下文
  • 子块：150–250 token 句界滑窗（15% 重叠）
  • 不跨标题边界；list / code / 公式原子保留
  • 标题路径前置，解决小块「信息孤岛」
多模态「双轨」策略
类型检索用（向量化）问答用（喂模型）
图片VLM 图像描述原图 base64
表格VLM 摘要MinerU HTML
代码功能说明+核心代码原始完整代码
公式自然语言含义原始 LaTeX
检索要「小而精」，问答要「全而准」—— 父子切片 + 双轨富化正是为化解这对矛盾。

难点 ③ / Hard Problem向量 + 关键词混合检索与重排

不是「调个 API」，背后是一条多级检索链

① LLM 查询规划
析出 关键词(BM25) + HyDE 陈述句(向量)
② 双路并行召回
Qdrant 向量 ‖ SQLite FTS5 关键词
③ RRF 融合（k=60）
两路排名融合成统一候选集
④ qwen3-rerank 重排
top_k 15 → top_n 5
⑤ Small-to-Big
命中子块 → 回填父块全文作上下文

↑真机踩坑修复

  • 中文 BM25 零召回 → jieba 预分词
  • 关键词路召回 0 → 20
混合检索 + 重排是对标大厂的标准做法 —— 而且我把它可视化了（见下一难点）。

难点 ④ / Hard Problem场景 AI Agent · 课程管家

会「自己查漏补缺」的多轮检索 Agent

1
首轮检索
5 个信息槽（考核/作业/考试/联系方式/通知）并行双路检索 + 去重合并
2
完整度自评
LLM 评估「信息够不够」，输出缺口分析 + 置信度
3
规划补检索
对缺失项自动生成新检索词，第二轮、剔除已给片段
4
收敛输出
信息足够则停，整合两轮 → 结构化课程卡片 JSON

⚙「工具调用」叙事

每步表达为 Agent 自主选用的工具，体现 ReAct 式「规划→行动→反思→再行动」闭环：
keyword_search() vector_search() expand_query() evaluate_coverage()
课后复盘亦含顺序 Agent：一天连续生成多节讲义，前序提示词与已生成讲义滚动作上下文，保证风格语境一致。

07 / Trade-offs设想 vs 落地

从设想到落地 —— 我做了哪些取舍

✅如约兑现
  • 通用底座全链路
  • 课后复盘
  • 课程管家
✂️主动取舍
  • 模块八 AI 考官：体量近一个毕设，时间风险过大
  • 音视频转写：基础链路优先
  • 选择把已做的做扎实，而非铺大摊子
➕反而超额
  • 三套可视化透视
  • 多 Provider 问答切换
  • 父块自定义索引
  • 格式漂移监控 · 中文检索修复
工程能力不只是「全做完」，更是「在有限时间里做对取舍、把核心做到可靠」。
