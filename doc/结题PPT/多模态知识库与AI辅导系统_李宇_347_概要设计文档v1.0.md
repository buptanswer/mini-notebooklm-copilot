# 面向大学生的多模态课程知识库与 AI 辅导系统（Mini\-NotebookLM）阶段概要设计

<a id="_Toc226689561"></a>
# 1、系统概述

<a id="_Toc226689562"></a>
## 1\.1、系统简介

本项目面向大学生课程学习场景，设计并实现一个本地运行的多模态课程知识库与 AI 辅导系统。系统核心目标不是做一个泛化的“聊天机器人”，而是围绕大学生在日常学习中的真实痛点，构建“资料接入 \- 结构化解析 \- 混合检索 \- 场景化辅导”的完整闭环。

系统支持将 PDF、PPT、Word、图片等课程资料导入知识库，经文档解析、结构标准化、结构感知切片、向量与关键词混合检索后，提供通用问答能力；在此基础上，进一步实现三个面向课程学习的场景化模块：

1. AI 伴学·课后复盘：帮助学生围绕本节课资料进行结构化复习与答疑，并自动生成复习笔记。
2. AI 考官·期末冲刺：支持题库构建、模拟组卷、答卷判分和知识漏洞分析。
3. AI 管家·课程提醒：从课程通知、教学大纲、截图等碎片资料中自动提取关键信息，形成课程信息卡片与提醒事项。

本系统采用前后端分离架构，在 Windows 本地环境下运行。前端负责知识库管理、对话交互、任务查看和结果展示；后端负责异步任务调度、文档解析、索引构建、检索问答和场景 Agent 流程编排；向量检索与大模型推理能力通过云端 API 获取。

<a id="_Toc226689563"></a>
## 1\.2、系统目标

<a id="_Toc226689564"></a>
### 1\.2\.1、功能目标

1. 支持课程资料的统一上传、存储、异步解析和状态追踪。
2. 将 MinerU 返回的原始解析结果转换为自研标准化中间表示（IR），为后续检索和溯源奠定基础。
3. 实现 Parent/Child 双层切片、向量检索与 BM25 关键词检索的混合召回能力。
4. 实现带来源溯源的多模态问答能力，支持页码、坐标、图片等证据展示。
5. 实现课后复盘、期末冲刺、课程提醒三个场景化模块，体现项目的垂直特色和 AI Agent 特征。

<a id="_Toc226689565"></a>
### 1\.2\.2、性能目标

1. 通用问答首字返回时间目标为 3~6 秒。
2. 课后复盘首轮分析响应时间目标为 5~10 秒。
3. 模拟组卷生成时间目标为 10~30 秒。
4. 课程信息提取响应时间目标为 5~15 秒。
5. 本地单用户环境下支持不超过 3 个活跃浏览器标签页并发操作。

<a id="_Toc226689566"></a>
### 1\.2\.3、工程目标

1. 采用清晰的分层设计，便于概要设计后直接进入原型编码阶段。
2. 功能结构图、模块设计、数据库设计、接口设计保持前后一致，可直接支撑课程考核。
3. 在概要设计阶段精确到“模块、表、核心接口、核心数据结构”层面，为后续详细设计和编码预留空间。

## 2\.2、软件总体架构

1. 表现层：前端页面、对话界面、任务中心、来源预览、场景入口。
2. 应用层：知识库管理、文件管理、问答服务、复习服务、组卷服务、课程提醒服务。
3. 核心处理层：MinerU 结果解析、IR 标准化、结构感知切片、混合检索、重排序、多模态问答编排。
4. 数据层：SQLite、Qdrant、文件系统。
5. 外部服务层：MinerU、阿里云百炼模型服务。

## 2\.6、设计思想

<a id="_Toc226689579"></a>
### 2\.6\.1、分层设计思想

系统采用前端表现层、后端应用层、核心处理层、数据层、外部服务层分层设计。各层职责单一、边界清晰，避免将上传、解析、检索、问答、UI 渲染混杂在同一模块中。

<a id="_Toc226689580"></a>
### 2\.6\.2、标准化中间层思想

系统不直接将 MinerU 原始输出写入向量库，而是先转换为标准化 IR。这样做的目的有三点：

1. 屏蔽第三方返回格式变化对系统的直接影响。
2. 为切片、索引、溯源和场景模块复用统一数据结构。
3. 为后续接入其他解析器或扩展音视频资料预留兼容空间。

<a id="_Toc226689581"></a>
### 2\.6\.3、质量优先思想

相较极限追求低延迟，本项目更强调问答的准确性、可解释性和对复杂图表内容的支持，因此采用“混合召回 \+ 重排序 \+ 多模态理解”的技术路线。

<a id="_Toc226689582"></a>
### 2\.6\.4、场景化 Agent 设计思想

系统不是简单地把知识库检索包装成聊天框，而是围绕“复习、备考、提醒”三类任务，将 AI 的多步操作流程产品化，使其更贴近大学生真实学习过程。

<a id="_Toc226689583"></a>
## 2\.7、实现思路

1. 学生将资料上传到指定知识库。
2. 后端发起异步解析任务，调用 MinerU 获取结构化结果。
3. 系统对解析结果进行 DOM 重建与 IR 标准化，提取标题路径、页码、坐标和多模态资产。
4. 基于标准化 IR 进行 Parent/Child 切片和多模态文本代理生成。
5. 将 Child Chunk 写入 Qdrant，将文本和元数据写入 SQLite 与 FTS5。
6. 用户提问时执行向量检索和关键词检索，再通过重排序获取最相关片段。
7. 系统映射回 Parent Chunk，并携带图片、页码、坐标等上下文组织 Prompt，调用多模态模型生成回答。
8. 三个场景模块在通用知识库能力之上，通过专用 Prompt 和流程编排实现差异化功能。

3. 为图片生成描述文本，为表格生成摘要文本。

## 3\.4、模块四：索引入库与混合检索

3. 在查询时并行执行向量检索和 BM25 检索。

## 4\.3、数据存储设计

1. 原始上传文件、MinerU 解析结果、IR 文件、Chunk 文件、答卷图片等采用文件系统落盘，便于大文件管理和溯源。
2. 业务对象与关系映射采用 SQLite 管理，便于本地部署与课程项目实现。
3. 面向语义检索的数据采用 Qdrant 存储，避免将向量直接塞入关系型数据库。
4. 所有向量记录必须能够映射回 Child Chunk，所有 Child Chunk 必须映射回 Parent Chunk 与原文页码。
5. 对重要数据采取“先文件后入库”策略，避免解析过程中出现半成功半失败状态。

# 6、其他设计

<a id="_Toc226689659"></a>
## 6\.1、异步任务与容错设计

1. 文档解析、图片富化、向量化、题库构建、答卷判分均采用异步任务处理。
2. 对 MinerU 与模型 API 调用设置有限次重试。
3. 当 Qdrant 不可用时，系统降级为 FTS5 关键词检索。
4. 当坐标提取失败时，来源溯源降级为“页码 \+ 文本片段”模式。

<a id="_Toc226689660"></a>
## 6\.2、安全与数据保护设计

1. API Key 保存在本地环境变量或配置文件中，不写死在前端代码中。
2. 上传文件限制类型和大小，降低异常文件对系统的影响。
3. 关键操作如删除知识库、删除文档需进行二次确认。
4. 场景层数据与通用知识库数据逻辑隔离，避免污染检索结果。

<a id="_Toc226689661"></a>
## 6\.3、性能与可扩展性设计

1. 采用“异步任务 \+ 本地缓存 \+ 分层存储”减轻单次请求压力。
2. 采用 Parent/Child 双层切片提升检索效率和回答完整性。
3. 标准化 IR 设计使系统未来可接入其他解析器或扩展音视频转写功能。
4. 各场景模块建立在统一知识库底座上，便于后续继续扩展新的学习场景。
