## Slide 7 — 难点①：MinerU 解析 → 自研 IR 标准化与文档树重建 ★重点

**标题**：难点一 —— 把"扁平、会漂移"的解析结果，重建成结构化文档

**左·遇到的真实坑（不是想象的）**：
- MinerU 输出**扁平**：标题层级永远 `title_level=1`，拿不到真实的章节树
- 输出格式**会漂移**：字段增删、同名字段语义变（如 list_type 出现 `reference_list`、Office 文档 title.level=2）
- Office 文档（DOCX/PPTX）**无坐标、无 origin.pdf**
- 跨页拆分块、跨页表格"空幽灵块"污染检索

**右·自研解法**：
- **双层"宽进严出" IR**：Raw 层 `extra=allow` 容错接收，IR 层严格 Pydantic 校验，脏数据绝不入库
- **LLM 文档树重建**：用大模型理解标题语义，重建多级 DOM 树，注入 `header_path` 面包屑
- **坐标锚点**：保留 bbox 供前端高亮溯源；Office 文档自动 OCR 转 PDF 拿坐标
- **MinerU 格式漂移监控**：每次解析跑 19 项语义校验 + 探针日志，官网文档滞后/有误时以实测为准

**配图**：解析透视截图（文档树 + bbox 画布）。

**讲解提示**：这是"难点必讲至少一个"的首选。强调"官网文档不可信、靠实测反推格式"这一点最能体现工程深度。

## Slide 8 — 难点②：结构感知父子切片 + 多模态富化 ★重点

**标题**：难点二 —— 切得准，才检索得准；多模态分轨处理

**上·父子切片（Small-to-Big）**：
- **父块**：按 N 级标题聚合（文档级可调粒度），语义连贯、给问答模型补全上下文
- **子块**：150–250 token 句界滑动窗口（15% 重叠），面向向量检索的高特异性小块
- **不跨标题边界**；list / code / 公式 作为**原子块整体保留**
- **标题路径前置**：`embedding_text = "{header_path}\n{retrieval_text}"`，解决小块"信息孤岛"

**下·多模态"双轨"策略（检索用富化文本 / 问答用原始资产）**：

| 类型 | 检索用（向量化） | 问答用（喂大模型） |
|---|---|---|
| 图片 | VLM 生成的图像描述 | 原图 base64（多模态路） |
| 表格 | VLM 摘要 | MinerU 原始 HTML（信息更全） |
| 代码 | LLM 功能说明 + 核心代码 | 原始完整代码 |
| 公式 | LLM 自然语言含义解释 | 原始 LaTeX |

**讲解提示**：强调"检索要小而精、问答要全而准"这对矛盾，父子切片 + 双轨富化正是为化解它。

## Slide 9 — 难点③：向量 + 关键词混合检索与重排 ★重点

**标题**：难点三 —— 不是"调个 API"，背后是一条多级检索链

**检索链（流程 + 每步意义）**：
1. **LLM 查询规划**：不直接拿用户原话检索，先让大模型析出"关键词（给 BM25）+ HyDE 式陈述句（给向量）"
2. **双路并行召回**：向量检索（Qdrant 余弦）‖ BM25 关键词（SQLite FTS5）
3. **RRF 融合**（k=60）：把两路排名融合成统一候选集
4. **qwen3-rerank 重排**：对候选二次精排，top_k=15 → top_n=5
5. **Small-to-Big**：命中子块 → 回填其父块全文作问答上下文

**右下·真机修复（体现踩坑深度）**：
- 中文 BM25 **零召回** → jieba 预分词修复（关键词路召回 0 → 20）

**配图**：检索透视六阶段动画截图（向量空间 / 重排连线）。

**讲解提示**：点明"混合检索 + 重排"是对标大厂的标准做法，并且我们把它**可视化**了（见难点五）。

## Slide 10 — 难点④：场景 AI Agent —— 课程管家多轮检索 ★重点（你想强化的核心卖点）

**标题**：难点四 —— 会"自己查漏补缺"的多轮检索 Agent

**左·Agent 工作流（不是单轮问答）**：
1. **首轮检索**：5 个信息槽（考核方式 / 作业 / 考试 / 联系方式 / 通知）并行双路检索 + 去重合并
2. **完整度自评**：LLM 评估"信息够不够"，输出缺口分析 `missing_info_analysis` 与置信度
3. **规划补检索**：针对缺失项自动生成新检索词，发起第二轮、剔除已给片段，融入上下文
4. **收敛**：信息足够则停，整合两轮结果输出结构化课程卡片 JSON

**右·"工具调用"叙事（Agent 化呈现）**：
- 把每一步表达为 Agent 自主选用的工具：`keyword_search` · `vector_search` · `expand_query` · `evaluate_coverage`
- 体现"规划 → 行动 → 反思 → 再行动"的 ReAct 式闭环，而非线性脚本

**底部**：课后复盘亦含**顺序 Agent**特征 —— 一天连续生成多节讲义，前序提示词与已生成讲义作为上下文滚动喂入，保证风格 / 语境一致。

**配图**：课程管家"Agent 决策透视"时间线截图。

**讲解提示**：Agent 是 AI 应用下一个竞争方向，是本项目刻意打造的差异化亮点；强调"多轮、自评、补检索"=真 Agent，不是套壳。
