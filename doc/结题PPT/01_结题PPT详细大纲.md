## 难点定位（老师问「最难的难点是什么」）

- **最难（深讲）= 结构感知父子切片 + 多模态四类双轨富化**（P8–P10）。理由：① 是检索召回上限的**地基**，切错全错；② 要同时满足「检索要小、问答要全」这对**冲突目标**；③ 结构感知 × 多模态分类 × 中文句界 × 原子性保护的**组合复杂度高**；④ 业界**无标准答案**，参数边界全靠自己实测调。这一步的设计思路原始记录见 `我的想法.md`，是本人独立思考的核心证据。
- 其余难点（IR 标准化 / 混合检索+重排 / 场景 Agent / 三套可视化透视）**文档详写、讲述一句带过**，并在 PPT 上注明「详见附录 / 详细设计」。

## 「证明是我做的」如何体现（老师核心关切）

1. **设计决策与思考**：`我的想法.md` 记录了父子切片、多模态双轨、可视化策略的原始设计推理。
2. **真实踩坑与诊断**（P17）：中文零召回 / 切片死循环 / 跨页空幽灵块 / 删除误删 / 格式漂移 —— 都带「问题→诊断→修复→数据」。
3. **逆向工程洞察**：MinerU 官网文档不可信，靠实测反推格式 + 持续监控（附录 E）。
4. **持续投入**：8 版迭代、30 commits、130+86 回归用例。
5. **诚实 AI 声明**：AI 作编码助手；架构/切片策略/诊断/取舍为本人 —— 延续需求分析报告附录原创说明口径（**这反而比假装零 AI 更可信**）。

## 检索评测实测结果（已跑，P16 已填入）

`benchmark_retrieval.py` 在 **程序设计基础实训** 课程（12 条人工标注 query / 19 篇已索引文档）上的真机结果：

| 配置 | Hit@1 | Hit@3 | Recall@5 | MRR |
|---|---|---|---|---|
| BM25 无 jieba | 0.00 | 0.00 | 0.00 | 0.00 |
| BM25 jieba | 0.67 | 0.92 | 0.73 | 0.79 |
| 向量 | 0.83 | 1.00 | 0.80 | 0.90 |
| 混合 RRF | 0.75 | 1.00 | 0.80 | 0.86 |
| 混合 + 重排 | 0.75 | 0.92 | 0.80 | 0.84 |

诚实口径：本集小而干净，向量已近上限，混合/重排未再超过它（其价值在更大/更嘈杂语料才显现）；最稳硬结论是 **jieba 让中文 BM25 命中率 0→100%**，完整管线 **Top-3 命中率 100%**。gold set 见 `backend/tools/benchmark_gold_set.json`。
